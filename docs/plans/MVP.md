## 三个脚本的批量启动

从「脚本管理」编辑 MaaEnd、MAA 和 BBchannel 的记录，分别在「模拟器启动」中选择能打开对应实例的 LNK 或 EXE 并设置等待秒数。回到总览点「批量启动」，核对即将启动的配对、参数和工作目录后确认。每组先提交模拟器启动，等待该组设定的时间，再提交脚本启动。预览只列入具备启动条件且已配对的脚本。MAA 如果自身也配置为启动同一个模拟器，先核对那项设置。

每个目标仍使用 Windows 各自的权限流程。派发前重新核对管理记录、快捷方式和工作进程，已运行或状态未知的脚本不重发。一次批量中相同的启动目标与参数会拒绝派发。当模拟器已提交而软件未能启动，核对后可单独启动软件。每组结果可从主窗口底部的提示查看，「已提交」表示 Windows 接收请求，脚本运行状态由后续采样确认。MAA 回环可保持关闭。

锁定还原和 Release 构建通过，零警告、零错误。129 项常规测试通过，3 项现场用例按条件跳过。隔离桌面烟测覆盖无配对时按钮禁用、单实例唤醒和重开。另用三个自有配对从总览确认并启动六个 Windows 夹具，每个夹具在对应工作目录写入收到的参数。常规测试覆盖按组顺序、并发点击、已运行脚本、快捷方式变化、重复模拟器入口和部分提交后的重试。受限环境的测试宿主连接及单实例唤醒失败，正常 Windows 环境复测通过。真实脚本及模拟器组合由所有者配置后验收。

配对启动时，卡片按钮在 Windows 接收模拟器启动请求后显示距脚本启动的剩余秒数。批量启动也在当前组显示相同倒计时。倒计时和实际等待使用同一单调时钟，等待中按钮禁用，到期进入「正在启动脚本」。确定性用例覆盖等待接受、剩余秒数、系统时间回拨、到期、拒绝和取消。隔离桌面夹具观察到按钮从 6 秒减至 5 秒，且等待期间脚本尚未派发。Release 构建零警告、零错误，130 项常规测试通过，3 项现场用例按条件跳过。

## Phase 4 按证据开放适配

所有者当前优先使用批量启动。下列软件专属任务能力和真实回环联调暂缓。

MaaEnd 单个框架任务的只读切片已通过自然完成和手动取消。MAA 6.23.1 的配对、空队列和 HeartBeat 已通过自有夹具，下一步是获准后验证真实客户端连通性。MaaEnd 指定实例启动可能因错名回退、已有窗口的单实例行为或提权时的参数传递而触发错误目标，待具备明确安全夹具和授权后再推进。

1. **先交付 MaaEnd 只读任务观测。** 从 `InstallationCatalog.Inspect` 的 GUI/资源版本开始，在 Adapters 编写版本化解析，Infrastructure 按取消令牌追读文件，Core 复用 `SessionState` 的时间与会话约束，Desktop 的 `LiveDesktopData.ToScript` 只显示已验证的状态。先用脱敏日志回放区分会话、实例、任务 ID 和来源，覆盖轮转、截断、UTF-8 断块、重放及重启。缺终态保留未知，取消单列。真实日志访问与任务执行分别授权。
2. **再核实 MaaEnd 的启动能力。** Phase 0 记录了指定版本的 `--autostart`、`--instance`、错名回退及提权丢参数风险。复核实际版本、唯一精确实例名、原工作目录、启动前后动作及当前 GUI 状态。先试安全夹具的参数保真，再由所有者指定可执行的测试实例。只有真实验证正确实例、既有 GUI 和权限交接后开放对应按钮。已有 GUI 只被唤起、参数丢失或实例名失配即停止派发。开始、取消、完成、失败分别按证据开放。
3. **MAA 先接心跳，再接一个明确动作。** Phase 0 的协议证据对应 6.23.1，Python PoC 仅验证回环形状。按安装版本核对客户端轮询与回报字段。Infrastructure 承担可取消的服务和请求限制，Adapters 维护配对、唯一命令 ID、重试去重和会话归因。复用 Core 的远程指令状态与游戏任务状态。服务默认关闭，仅显式启用后绑定 `127.0.0.1`。验证端口冲突、未知配对、过大请求、重复/乱序回报、失联、关闭监听。配对字段只用于关联；评估当前协议能提供的认证强度和同机调用者风险后再开放有副作用的命令。新增宿主依赖前确认运行时部署与锁文件。
4. **MAA 真实验收分两次。** 经授权由所有者在原 GUI 配置地址，先验空队列和 HeartBeat；再以明确账户、空闲设备和可接受的模拟器影响授权单一动作。收到轮询、客户端回报和任务终态分别记录。超时保持结果未知，禁止盲目重发。无可靠任务关联就保留遥测或通用管理。
5. **BBchannel 继续原 CMD 和已确认工作进程。** 无需等待专属接口。任务状态显示未接入。版本改变或出现可复验正式接口时再评估。

每个能力的出口是版本范围、脱敏重放、自有夹具、真实软件和游戏任务五项证据分别登记。只对验证过的组合启用。接口改变、权限不明、设备冲突或涉及未经授权操作时停止该能力，保留其余软件可用。[既有调查与样本范围](../PHASE0_REPORT.md)


- 已用合成数据验证核心状态迁移和 Windows 临时文件追读，包含从文件到任务状态的联动。锁定还原通过，Release 零警告、零错误，85 项常规测试通过。常规运行跳过两项显式现场测试，其中自有进程窗口夹具单独启用后通过，真实安装观测保持关闭。Windows 文件身份夹具在受限沙箱内未通过实际路径核验，随后在正常 Windows 文件系统环境复测通过。
- 2026-11-26 真实只读验收使用 Release 构建的 Windows 日志读取器与 MaaEnd 适配器。目标版本匹配，从日志末尾接入时保持未知。第一轮捕获执行中及所有者手动停止后的已取消。第二轮在设备恢复连接、重新接入当前 GUI 实例后，捕获同一框架任务的匹配起止事件并输出已完成。两轮只保留状态和脱敏计数。失败暂为源码与合成夹具级证据，验收范围为单个框架任务。桌面卡片使用同一观测结果。
- 收尾审阅补充了异常 `reason` 类型的回归，畸形开始事件不能为后续终态建立关联。真实失败等自然发生时补证。整轮结果仍需单独的队列起止与归属证据，当前界面保持单任务口径。

### MAA 回环连通性验收

2026-11-26 普通启动回归通过。所有者从本地 Release 的 MAA 卡片点击「启动软件」，BAM 识别 MAA 6.23.2 进程并显示「已启动」，MAA 按原配置打开雷电模拟器并进入日常运行。证据范围为启动和进程显示。日常终态与真实回环心跳仍未验证。

本地夹具使用合成 `user/device` 和系统分配的 IPv4 回环端口。6 项 HTTP 夹具覆盖空队列、配对、待轮询和待回报、重复投递、重复与冲突回报、未知标识、报告丢失超时、非法或过大请求、慢请求，以及端口冲突、重启和停止后的重新绑定。锁定还原成功，Release 零警告、零错误，92 项常规测试通过。隔离桌面烟测确认回环默认关闭，并通过单实例、托盘和退出验证。

设置页在监听关闭时也显示两条可复制的地址。界面测试覆盖默认端口、输入非法端口、所选端口变化、使用实际绑定端口和停止后恢复预览。端点、配对和心跳协议沿用现有实现。

获准连接真实 MAA 6.23.1 后，使用以下步骤。

1. 保留 MAA 原设置供恢复。打开 BAM「设置 → MAA 回环连通性」，填写希望监听的端口及 MAA 的用户和设备标识，点击「启用回环」。默认端口为 `18373`，可换为其他空闲端口。配对标识输入后清空，仅在监听会话内保留。
2. 从 BAM 设置页复制「取任务地址」与「回报地址」，分别粘贴到 MAA 的远程控制设置。修改端口后两条完整地址同步更新。先观察 BAM 的最近配对轮询，此时返回空队列。
3. 在 BAM 点击一次「发送心跳」，观察界面从排队变为已提供，再变为收到回报。探测在一分钟后过期。空载荷仅表明没有返回远程顺序任务标识，手动任务及游戏结果保持未知。
4. 结束时点击「停止监听」，恢复 MAA 的原设置。验收记录只保留版本、状态和结果，涉及真实任务的指令另行验证。

框架依赖构建需 .NET 10 x64 桌面运行时和 ASP.NET Core 10 x64 共享运行时。协议基线见 [MAA 6.23.1 远程控制协议](https://github.com/MaaAssistantArknights/MaaAssistantArknights/blob/v6.23.1/docs/zh-cn/protocol/remote-control-schema.md)。

## Phase 5 最小调度

至少有一个经验证可安全派发的动作后，由所有者选择首个日常用例。Core 建立计划 ID、目标安装及动作、当地时间、启用状态、授权范围和独立执行记录。Adapters 在派发前重新检查版本、目标身份、配对和能力；Infrastructure 原子写入计划和触发记录；Desktop 复用既有控件显示下次执行、取消及结果。

首个无人值守用例优先选择已运行的授权实例和通过验收的接口。遇到需要交互 UAC 的目标，计划记录跳过原因。涉及提权的调度按 F-06 另行评审，覆盖持久配置、可导出的脱敏会话证据和授权撤销，保持默认 `asInvoker` 及现有高权限写入边界。

先做单机单次或每日触发，使用注入时钟。按计划和本次应触发的时间生成唯一键，先持久记录再派发。重启时未闭合记录显示未知，默认跳过错过的时间。锁定目标和已知共享设备，不确定设备归属、遇 UAC、已有任务或需人工确认时跳过并给出原因。取消排队任务立即生效；执行中仅调用已验证的取消能力。测试双触发、夏令时、时钟回拨、睡眠恢复、写盘失败、进程崩溃及重启。验收以同一触发最多派发一次、没有静默重试、用户能查到每次结果为准。

## 最小分发

按 V-01 做基础稳定性检查，在干净 Windows 11 x64 验运行时、解压启动、配置重开与退出。清点第三方声明、隐私、文件清单和包校验值，更新使用说明及已知限制。所有者选择许可证并授权后再建立公开检查点或发布。混合 DPI 全矩阵、长跑优化、安装器和自动更新可继续独立迭代。主要风险是过早依赖尚未通过真实联调的能力，因此计划以逐项验收决定开放范围。
