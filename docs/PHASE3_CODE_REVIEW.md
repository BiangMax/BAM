## 权限、身份与启动

- BAM 清单为 `asInvoker`、`uiAccess=false`。直接从提升的父进程启动可以继承其权限；目标带提权标记时，启动代码使用单次 `runas`，Windows 取消码 1223 映射为拒绝。状态栏显示本次 BAM 进程的提升状态。管理员会话中的新日志可在退出前查看。
- 观测使用受限查询与同步访问；检查目标令牌只申请 TOKEN_QUERY 并读取 TokenIntegrityLevel。窗口能力要求令牌可读且目标完整性不高于 BAM。跨完整性投递窗口消息受 UIPI 约束，激活按钮沿用保守的完整性门槛。即使等级相同，系统仍可能拒绝前台切换。强制结束单独探测 TERMINATE 权限，读取 CPU、工作集不依赖该权限。句柄访问受限或同名候选不能识别时降级未知。[进程访问权限](https://learn.microsoft.com/en-us/windows/win32/procthread/process-security-and-access-rights) · [窗口消息与 UIPI](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-postmessagew) · [前台限制](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)
- 所有者曾验证普通 BAM 可读三个空闲 GUI 的资源，MaaEnd、MAA 的窗口按钮禁用，BBchannel 可用；提升 BAM 后前两者恢复。这符合上述能力判定。历史 Phase 0 有目标提权线索。本轮只读时三个 GUI 均停止，因此各实际目标的令牌、具体失败调用、跨权限并发启动及真实 UAC 取消仍缺现场证据。
- 扫描用名称筛候选，控制用完整映像路径、PID、UTC 创建时间复核。强制结束在同一已复核句柄上调用 TerminateProcess。窗口操作复查 HWND 所属 PID 与原句柄存活；Windows 无原子“检查 HWND 并投递”接口，仍有窗口瞬时变更的竞态。关闭超时反馈超时；重启需确认原句柄退出并最终复查安装无其他实例。与外部手工启动之间仍有最后一次枚举到系统创建的时间窗。
- BBchannel 保留原批处理、工作目录及受限参数，通过系统目录的 cmd.exe 和禁用 AutoRun、延迟展开的模式执行。拒绝连接符、变量展开、控制字符和失配引号。按已知工作 EXE 接管短命启动器之后的实例。夹具验证了中文空格路径、带引号参数与工作目录；实际批处理内容及启动后的行为归第三方维护。
- 普通用户可编辑安装记录和快捷方式。单实例 IPC 只有激活事件，正式启动参数没有第三方派发入口。启动、重启须用户明确核对有效路径与参数；通用程序按用户选择的工作 EXE 建立绑定。BAM 不认证第三方二进制、批处理内容或其安装目录的写入者，管理员运行时尤其需信任目标及目录。

## 并发、监控和持久化

同一安装的忙标记跨越提交、等待、重启；修改配置和移除受同一门保护，旧界面命令检查安装对象及实例身份。启动请求等待 UAC 时释放监控门，25 秒未确认工作进程则保留未知并暂停重复启动。退出取消并有界等待三秒；超时路径让进程退出回收剩余资源，已提交给 Windows 的请求无法撤销。

CPU 使用单调时钟和逻辑处理器数，换实例、首样、间隔异常及缺样为空；工作集按 MiB 汇总，覆盖不足不显示总量。曲线按 120 秒有界缓存，托盘降频并停止可见绘制。进程与令牌句柄、快照、HICON、COM 对象可追溯到释放点，图标字典上限 128。未进行 24 小时资源泄漏判定。

正常用户会话由单实例写配置，安装变更串行、临时文件替换并留备份，未来 schema 保护原件。日志按 4 × 约 1 MiB 轮转、14 天清理、最多回放 2,000 条。产品控制结果使用结构化原因；窗口标题、参数、路径等在本机详情/确认中可见。用户自行填写的显示名、参数仍可能含私人信息，反馈前需脱敏。

## 启动流程补充复核

R-07 按安装持有操作标记，进入平台前取消或返回确定拒绝时释放。进入平台后抛出失去结果的异常或 Windows 返回不明确时，在清理路径保留挂起状态。之后以完整映像路径和进程身份核对观测结果，只有唯一工作进程匹配才恢复正常能力。一次枚举为空、仅同名或经过 25 秒都不能解除重复启动保护。模拟器提交结果未知时，停止后续软件派发并在会话内暂停该安装的启动操作，已确认进程的窗口和关闭能力仍按各自证据判定。保护范围为当前 BAM 会话。有关自动派发的跨重启记录留在 F-03。

R-06 新导入的 LNK 分别继承参数和工作目录，两个字段可独立覆盖。已有配置无法辨别保存值的来源，保留原值，用户可在编辑页选择跟随快捷方式。打开启动确认时使用最近一次解析的有效入口。执行前重新读取并核对目标、权限标记、有效参数和工作目录，提交软件启动前再核对一次。旧确认内容发生变化时停止派发并刷新，模拟器等待和重启退出等待同样适用。批处理语法限制保持有效，仍使用确定的目录和参数。

启动前后取消、确定失败、提交结果未知、并发点击、同名不同路径、快捷方式字段继承及覆盖、旧配置读取和等待期间变化均有夹具覆盖。Windows 原生 UAC 交互和真实脚本任务仍按授权单列验证。

批量启动经过同一启动门。一次确认冻结已配对的管理记录和软件入口，各组依次按当前进程观测与入口复核派发，禁用同一次批量里的相同启动目标及参数。BAM 只发启动请求，工作进程的运行仍由映像路径、PID 与创建时间确认。已提交模拟器、软件尚未确认时，保留该安装的配对启动限制，普通软件启动仍按自身证据判定。权限仍按各目标单次处理。三个自有配对实走 WPF 确认和 Windows 派发，验证六个进程收到各自参数与目录。真实快捷方式、模拟器实例和 UAC 请求待现场验证。
