# BAM 稳定版收尾路线

**产品定位**　BAM 是面向 Windows 11 x64 的游戏自动化脚本管理器。用户从总览手动启动和查看 MaaEnd、MAA、BBchannel 及其模拟器。界面保持清晰好看，常驻托盘保持低开销。脚本内部配置、游戏任务与更新由原工具负责。

**当前基线**　Phase 3 的检查点为 `phase-3-complete`。Alpha 2 已公开预发布，三组批量启动、配对倒计时和三组模拟器资源采样满足已验的日用需求。Release 构建零警告、零错误，134 项常规测试通过，4 项按条件跳过，隔离桌面烟测通过。公开 ZIP 的干净系统实测另有待办。[实施与验证记录](plans/MVP.md) · [统一待办](BACKLOG.md) · [Alpha 2 发布](https://github.com/BiangMax/BAM/releases/tag/v0.1.0-alpha.2)

## 稳定版范围

- 一处配置、启动和查看三组软件。保留快捷方式发现、手动添加和重新定位，以及能力允许时的窗口与进程操作。MaaEnd 和 BBchannel 按配对入口倒计时，MAA 沿用自己的启动设置。
- 现有监控显示可确认的进程、资源、时间和事件。权限不足、入口变化、启动未确认和部分失败都有可解释的反馈。保留身份核验、同实例串行和防重复派发。
- 保留现有桌面设计系统、原生窗口与托盘交互、有限历史及本地配置。针对影响理解或操作的布局、状态、焦点和文案做小幅优化。
- **原 Phase 5 已取消。** 定时任务、无人值守自动调度、高级任务队列及跨设备调度不再计划实现。休眠唤醒进入桌面恢复验收。
- **Phase 4 基础范围已交付。** MAA 回环实验已移除，产品聚焦脚本与模拟器的本地启动、关闭和资源观测。MaaEnd 只读观测默认关闭，BBchannel 保持通用管理。

## 收尾顺序与发布门槛

| 顺序 | 工作 | 怎样算完成 |
|---|---|---|
| 1 | 批量启动反馈及必要交互 | 从现有结果入口看清每组的请求状态和随后观测到的进程结果。区分提交后待确认、确认运行、未能确认、跳过与明确失败。用自有进程验证部分失败及结果重新打开。 |
| 2 | 便携包、升级与桌面恢复 | 先复测 Alpha 2 公开 ZIP，再验收最终候选。干净 Windows 11 x64 解压启动及退出重开通过。用隔离的 Alpha 2 配置副本验证设置、脚本、配对和监控保留，以及备份和回退。实际休眠唤醒与 Explorer 重启后恢复监控、托盘和原窗口，检查无重复启动或配置损伤。 |
| 3 | 短时性能、兼容性及缺陷 | 核对常用显示缩放、键盘、颜色对比与托盘流程，按场景补测混合 DPI 和多开。对照前台与托盘资源基线，修复可复现的回归和实质开销。关闭影响主流程或数据安全的缺陷。 |
| 4 | 正式发布准备 | 由所有者确定 BAM 自身许可证。核对实际打包的依赖、字体、图标及第三方通知。更新安装使用、升级回退、版本说明和已知限制。稳定版打包、CI 和发布资产按同一源码标签核验，通过后由所有者授权发布。 |
| 5 | 长期维护 | 以稳定版标签和实际发布记录建立维护基线，按影响和复现证据从长期维护待办接续。 |

首个稳定版以 `0.1.0` 为目标。锁定还原、Release 构建、两套测试和相关 Windows 烟测均需通过。错目标、重复启动、配置丢失、常用启动或托盘恢复失效属于发布阻塞。实机环境不足时记录未验项和对发布的影响。每轮交付列出已完成、未完成或暂缓、证据及下一步。[稳定版待办](BACKLOG.md#稳定版待办) · [实施记录](plans/MVP.md)

## 短时性能基线

现有两个 10 分钟自有负载短跑中，BAM 前台 CPU 为 0.052%–0.103%，托盘为 0.009%–0.032%，工作集约 198–217 MiB。复测对齐负载和权限，记录实际设备或已确认配置、Windows 版本、DPI、采样模式、CPU、工作集、私有提交和句柄，分别测 BAM 与受管理工具。前台 CPU ≤1% 和托盘 CPU ≤0.3% 继续作为空闲参考。8 小时与 24 小时验证暂缓，有长期增长或恢复缺陷证据时再评估。[短跑测法与实测](plans/MVP.md#自有负载短跑)

按现场问题复测采样节奏、启动速度或日志压力。采样参考为前台 1 秒、窗口不可见 5 秒、托盘 10 秒、安装路径校准约 30 秒。启动或交互明显退化时记录冷启动环境和点击反馈耗时。已有 60 秒合成日志验收覆盖读取恢复、回放上限和筛选。[短时稳定性证据](plans/MVP.md#短时稳定性与兼容性验证)
