## Phase 1 实施顺序（已验收）

1. 用已获准环境核对 dotnet --info、10.x SDK 和还原源。设置 global.json、.editorconfig、Directory.Build.props、Directory.Packages.props、.slnx；SDK 不可用时保持调查工程原状。
2. 建 Desktop/Core 和第一个测试项目；Adapters/Infrastructure 随首个实现接入，依赖方向依据架构图。设置 AssemblyName、RootNamespace、nullable、目标平台与可重复构建配置。
3. 实现 ProcessIdentity、互相独立的状态快照、来源/时间、能力与拒绝原因。仅加入首批用例用到的接口；用同名不同目录和 PID 复用作为首批回归。
4. 验证 clean restore、Release build、test、publish；检查安装目录和私人文件不进入构建产物。记录版本与命令，接入最小 Windows CI，Phase 2 再开始实现设计稿。

## Phase 2 接手顺序

1. 依据 [UI 设计规范](UI_DESIGN.md)建立语义资源、明暗主题和统一控件样式。
2. 在 Desktop 建立主窗口、标题栏和导航，验证贴靠、高 DPI、键盘焦点和读屏。
3. 用明确标识的演示数据开发脚本卡、状态展示和托盘恢复。在发布配置中禁用演示数据源。
4. 复测单实例、锁定还原、Release 构建和既有测试。真实进程发现与控制从 Phase 3 起实现。

## 性能预算与测法

下表均为**待验收目标**。以固定配置的 Windows 11 x64 测试机为基准，采用 Release x64、三个脚本、无调试器，每项记录 Windows build、主题、DPI、采样配置、工作集和私有提交。BAM 与被管理工具的资源开销分别测量。

| 项目 | 初始目标 | 测量方法 |
|---|---|---|
| 空闲 CPU | 前台 10 分钟均值 ≤1% 整机；托盘 ≤0.3% | 预热 2 分钟，独立进程差分采样；分别测空列表、三卡和日志追读。 |
| 采样节奏 | 前台 1 s；窗口不可见 5 s；托盘 10 s；路径校准约 30 s | 切换显示状态检查计时器份数及耗时；进程退出事件不等下次曲线更新。 |
| 内存 | 三卡前台稳定工作集目标 ≤180 MiB，私有提交 ≤250 MiB；托盘报告实际值 | 初次布局后及 30 分钟后分别采样，不以主动清空工作集美化结果。 |
| 长期运行 | 8 小时初筛、24 小时确认；稳定负载下最后一小时私有提交中位数较第 1 小时增幅 ≤20 MiB，无持续句柄增长 | 固定日志输入与轮转、周期换页/托盘/恢复，记录每分钟内存和句柄。 |
| 启动和操作 | 冷启动到首个可交互窗口目标 ≤2.5 s；本地导航/点击反馈 p95 ≤100 ms | 冷/热分别测；冷启动注明缓存条件，外部软件响应单独统计。至少 30 次交互，报告样本数。 |
| 日志洪峰 | 1000 行/s 合成输入持续 60 s，UI 可操作、缓冲上限生效、超限计数可见 | 叠加轮转、截断、共享读失败与 UTF-8 半字符，校验重放和恢复。 |

## 测试层级与当前风险

- 每次构建运行核心单测、适配器事件重放、配置迁移/写入中断、重复/乱序命令用例。Windows 集成以自有窗口、短命启动器和同名双路径夹具覆盖；受控外部资源通过可取消的有界任务访问。
- 夜间或发布前验证窗口最小化与跨屏还原、前台请求被拒、无权限读取、原软件升级重启或移动、设备被占用、休眠恢复与长跑。热更后只保留仍有证据的能力。
- 高风险项是 MAA 启动即执行、两款安装的提权设置、MXU 错名回退或提权丢参数、脚本启动器名与实际工作进程不同、日志旧记录误报及回环指令重放。对应的阻断条件见[实机报告](PHASE0_REPORT.md)和[架构](ARCHITECTURE.md)。
- 性能预算超出时先定位常驻计时器、图表重绘、日志 I/O 及缓存，记录实测后再调整门槛。没有稳定来源的任务进度、剩余次数、失败统计以及卡死恢复维持关闭。
